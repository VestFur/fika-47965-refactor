# Fika 双人验收脚本（2026-10-26，一次性跑完 13 个功能区）

> 目的：用一局（约 40–60 分钟）把 `REBUILD-PLAN-20261026.md` §13 的验收矩阵尽量填满。
> 每项都写清「怎么做 / 看什么 / 什么算通过」，不需要你判断代码，只需按顺序做动作并在失败时把对应日志行贴回来。

---

## 0. 准备（5 分钟）

1. **两台机都装同一个包**：`release/Fika-47965-refactor-20261026-W35-immunityscope.zip`
   - 客户端 dll 应为 `6536EC02…`，服务端 `571F3C78…`（`Get-FileHash ... -Algorithm SHA256` 前 8 字节即可）
   - **两端包不一致会触发 W22 的新日志** `packet pool has no entry for …` —— 看到这行说明装错版本了，先重装再测。
2. **清日志**：两台机都把 `BepInEx\LogOutput.log` 改名或删掉，保证这一局的日志是干净的。
3. 主机建局，客机加入；**地图选海关/森林这类跑得开的图**，最后一局再测储备站/实验室之类的重图。
4. 说一句 `开始测试` 之后再进图，方便日志对齐。

## 2. 过场 / CG（覆盖：过场生命周期、跳过投票、主机免疫）

**这是最容易复现 bug 的一项，请单独记时间点。**

| # | 动作 | 通过标准 | 日志判据（客机 / 主机） |
|---|---|---|---|
| 2.1 | 触发第一个过场（如海关的开场 CG / 进入特定区域） | 两端都能播 | 客机 `[SyncDiag] local-process start` 出现 ≥1 |
| 2.2 | 过场播完 | 客机过场正常结束、能自由移动 | 客机 `[SyncDiag] local-process end … end=native` |
| 2.3 | **立即看主机**：主机能否被 bot 打死 / 能否正常受伤 | 主机**不再无敌** | 主机 `[SyncDiag] cutscene-immunity-release … role=host` 且 `wasImmune=1`（或 `cleared local sniper immunity … wasImmune=1`） |
| 2.4 | 过场中按跳过（如果该 CG 可跳过） | 跳过提示出现，两端一起跳过 | `CutsceneSkip` / `OnSkipIntention` 相关行 |

**失败时最需要的一行**：主机 `cutscene-immunity-release` 里的 `viewerHits=` 与 `wasImmune=`；若 `wasImmune=0` 而主机仍然无敌，说明免疫不是从这里释放的，请把整行贴回来。

## 3. 终点站转移（覆盖：点位状态三态、广播、entry-requirements）

| # | 动作 | 通过标准 | 日志判据（主机） |
|---|---|---|---|
| 3.1 | 走到某个终点站（如海关 transit 点） | 客机看到交互提示 | 客机 `[SyncDiag] point-apply` 出现该 pointId |
| 3.2 | 客机按交互 | 转移开始（或给出明确不可用原因） | 主机 `[TransitDiag] host answer=… pointState=enabled=…,isActive=…,configured=…` |
| 3.3 | 若被拒 | 客机看到原因 | 主机 `[TransitDiag] entry-requirements point=… reqs=…[类型 met=y/n tip=…] time=… hideIfNoKey=… waitAll=… maxGroup=…` |
| 3.4 | 转移完成 | 客机进到目标图 | 主机 `point-broadcast` 或客机 `point-apply` 有对应行 |

**W25 新增的第 3.3 行是关键**：它会直接告诉我们是**时间窗**、**钥匙**、**组队等待**还是**任务条件**没过。贴这一行就够定位。

## 4. 物品与背包（覆盖：known/searched、resync、失败记账）

| # | 动作 | 通过标准 | 日志判据（客机） |
|---|---|---|---|
| 4.1 | 拿地面战利品、开箱、捡尸体 | 拿到的物品**显示为已检视**（有名字，不是"未检视"） | `[SyncDiag] op=… bookkeeping … items=N known=a->b`，要求 **b == N** |
| 4.2 | 把物品放进背包/弹挂，卸下再装 | 重开背包仍显示正常 | 同 4.1 |
| 4.3 | 快速连续拾取 5–10 件 | 不出现"物品先消失、重开变未检索" | 若出现，贴该时间的 `bookkeeping` 与 `resync-begin` 行 |

**W26 新增覆盖**：如果主机卡顿导致某次操作超时（`FailLocally`），现在也会补记账。判据同上：`bookkeeping` 的 `known=b` 应等于 `items=N`。

## 13. 收尾（2 分钟）

两台机各跑一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\fika-evidence.ps1 -Log D:\EFT5.0-47965\BepInEx\LogOutput.log
```

把生成的 `.build\fika-evidence-<时间戳>.txt` 两份（主机 + 客机）发回来即可。

报告里每一栏的含义：

| 报告栏目 | 对应上面哪一项 |
|---|---|
| 过场生命周期 / 过场跳过投票 | §2 |
| 免疫释放 / 免疫武装 | §2.3 |
| 点位广播(主机) / 广播跳过原因 / 主机拒绝答复 / entry-requirements | §3 |
| 库存记账 / 库存 resync | §4 |
| 刷卡上行 / 哨兵权限 | §6 |
| 未知子包/构建不一致 | §0（装错版本时会亮） |
| 补丁安装失败 / 未捕获异常 | 任何异常的先看这里 |

**优先级**：如果时间有限，只做 **§2（过场+主机免疫）→ §3（转移）→ §4（物品）** 三节。这三节对应你最初报的三个 bug，其余功能可以下一次再补。
